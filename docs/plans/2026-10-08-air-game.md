# Air Game Implementation Plan

> **For agentic workers:** follow this plan task by task, one PR per task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restate SPI §33–47 (the Air Game) in `rules/air/`, with its charts
as data, NJHarman's air items seeded, a single stated switch from §32 and
§58, and every air ruling decided.

**Architecture:** the Mission 5 pipeline unchanged: source text, our prose
with `::: spi` badges, the overlap gate, the coverage report,
`EXTRACTION.md`, and charts transcribed as JSON with a schema and a test,
each read twice.

**Spec:** `docs/designs/2026-10-08-air-game-design.md`. Where this plan and
the spec disagree, the spec wins.

## Global Constraints

- No SPI text in the repo or on the site. Paraphrase, and cite case numbers.
- Every PR passes the gates in `AUTOPILOT.md`, with
  `check_coverage.py --sections` over the sections it draws on (0 uncovered).
- Examples are our own situations, never SPI's with new numbers.
- Tables are recorded **as printed**; corrections go in `data/errata/`
  overlays (SPI errata) or rulings (ours). Cells the second scan cannot
  confirm are listed in the table's `notes` and, if only a printed copy can
  settle them, in the `copy` group of `docs/autopilot/decisions.json`.
- Keep every rules file under about 70 cases.
- cna-engine's **Requests for cna** come before any task here, every run.

## Review Focus

1. **The Land and Logistics games must still read correctly without the
   Air Game.** A `::: note` pointer must never change a rule body. Check:
   `git diff main -- rules/*.md rules/logistics/` shows only added notes.
2. **The switch is one list.** `rules/air/00-overview-and-sequence.md`
   names every §32 and §58 passage the Air Game replaces; each named
   passage has its note, and nothing else does.
3. **Aircraft ids resolve.** Every aircraft type named in a table, the air
   reinforcement schedule or a scenario's air set-up has one
   `aircraft:<nation>:<slug>` row.
